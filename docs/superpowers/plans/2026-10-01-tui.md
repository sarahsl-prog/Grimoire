# Grimoire Terminal UI (TUI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Textual-based terminal client with two screens for v1, Search/Ask and Documents, launched with `grimoire-tui`. `grimoire --tui` and `grimoire tui` are shortcuts that start the same app.

**Architecture:** The TUI is a thin synchronous HTTP client over the existing REST API, exactly like the desktop GUI. It reuses `GrimoireClient`, `GuiConfig` and `GuiError` from `grimoire/gui/` (all three are Qt-free), so the TUI process never loads torch, Docling, ChromaDB, or PySide6. Every network call runs in a Textual thread worker and reports back by message. Textual lives behind an optional-dependency group so the server image and CI stay TUI-free.

**Tech Stack:** Python 3.12+, Textual 8.x, httpx (sync, via the existing client), Pydantic v2 (the server's own response models), Click (shortcut flag only), loguru, pytest + pytest-asyncio (`App.run_test()`).

**Decisions already made (from scoping):**

1. HTTP client only. No in-process agents. The API server must be running.
2. v1 screens: Search/Ask and Documents.
3. `grimoire-tui` is the canonical entry point. `grimoire --tui` is a shortcut.
4. The client sends a per-launch session id as an `X-Session-Id` header so server-side logs and traces can be correlated with the TUI's own log file (Task 1b). Server-side handling is a separate PR (see *Follow-up PRs*).
5. Populating `tag_count`/`chunk_count`/`tags` in the documents API is its own PR, not part of this one (see *Follow-up PRs*).
6. API key entry stays environment-only (`GRIMOIRE_API_KEY`) for v1. An in-app entry modal is deferred to v2.

## Global Constraints

- **No pipeline imports.** Nothing under `grimoire/tui/` may import `grimoire.agents`, `grimoire.core`, `grimoire.db`, `grimoire.cli`, `grimoire.config.settings`, or `grimoire.utils.logger`. Enforced by a subprocess import-hygiene test (Task 8).
- **Nothing logs to the terminal.** `grimoire.utils.logger` installs a stderr sink at import and the Click group's callback calls `setup_logger()`. Either corrupts a full-screen UI. The TUI configures its own file-only loguru sink before building the client (Task 2).
- **Raw exceptions never reach the screen.** `GrimoireClient` already raises only `GuiError`. Every worker also has a last-resort `except Exception` that logs with `logger.exception` and shows a generic message. Workers use `exit_on_error=False`, because Textual's default kills the whole app on a worker exception.
- **Nothing blocking on the event loop.** Every client call is in a `@work(thread=True)` worker. Widgets are touched only from message handlers.
- **`notify()` takes `markup=False` for anything from the server or a model.** Textual parses notification text as markup by default. Error messages, titles and answers must be passed with `markup=False`.
- **Thread workers cannot be killed.** An `exclusive=True` worker marks the old one cancelled but the HTTP call keeps running. Each worker checks `get_current_worker().is_cancelled` before posting its result so stale results are dropped.
- **`mypy --strict` must pass** over `grimoire/` including `grimoire/tui/`. Subclass generics explicitly (`App[None]`, `ModalScreen[None]`). A narrow, commented `# type: ignore[code]` is acceptable, a module-level exclusion is not.
- **Ruff / black:** same config as the rest of the repo (selects `E,W,F,I,N,UP,B,C4,SIM,S,C90`, max complexity 12, line length 88).
- **Timeouts:** reuse `GuiConfig` (connect 5s, read 30s, 300s for `/query/ask`).
- **Config:** `GRIMOIRE_API_URL` and `GRIMOIRE_API_KEY` via `GuiConfig.from_env()`. A `--url` option overrides the URL. There is **no** `--api-key` option, because command-line secrets leak into `ps` and shell history.
- **Tests:** `asyncio_mode = "auto"` is already set, so do not add `@pytest.mark.asyncio`. Guard TUI test modules with `pytest.importorskip("textual")`, the same way `tests/test_gui_app.py` guards PySide6.
- **Commits:** imperative, one line, no trailing period. One task per commit, never batch.

## Server facts the plan relies on (verified in the repo)

| Fact | Consequence |
|---|---|
| `GET /api/v1/documents` accepts `offset`, `limit`, `status`, `file_type`, `source_type`, `severity`, `cve_id`, `mitre_technique_id`. There is no title search and no category/tag filter. | Documents screen filters are server-side on `status` and `file_type` only. No free-text find in v1. |
| `DocumentResponse.tag_count` and `.chunk_count` exist in the schema but **no route populates them** (always `0`). `DocumentDetailResponse.tags` is likewise never filled. | Do not show tag/chunk columns. Showing zeros would be a lie. Listed as a server follow-up, not in scope. |
| `POST /query/ask` and `/query/search` accept `filter_dict` (keys: `tags`, `severity`, `source_type`, `cve_id`, `mitre_tactic`, `mitre_technique_id`, `content_date_after`, `platforms`). | Search screen gets a small filter row. The existing client methods do not send `filter_dict` yet (Task 1). |
| `ProcessingStatus`: `pending, processing, completed, failed, stale`. `FileType`: `pdf, docx, pptx, xlsx, html, md, txt, image, audio, video, other`. | Filter dropdown options. |
| `GET /documents/{id}` returns `DocumentDetailResponse` (adds `error_message`). 404 becomes `RequestRejected("Not found: ...")` in the client. | Detail modal. |
| `grimoire/gui/__init__.py` is docstring-only and `client.py`/`config.py`/`errors.py` import no Qt. | The TUI can import them directly with no refactor. |

## Task 1b: Send a session id header

**Files:**
- Modify: `grimoire/gui/config.py`, `grimoire/gui/client.py`
- Test: `tests/test_gui_config.py`, `tests/test_gui_client.py` (append)

**Interfaces:**
- `GuiConfig.session_id: str | None = None` (new frozen-dataclass field, default keeps every existing construction valid).
- `GrimoireClient._headers` adds `X-Session-Id: <id>` **only when** `session_id` is set, so the desktop GUI's requests are unchanged until it opts in.
- Validation lives in one place, `GuiConfig`: a `session_id` must match `^[A-Za-z0-9_-]{1,64}$`. Anything else raises `ValueError` at construction. This keeps CR/LF out of a header and out of the server's logs (header and log injection). The check goes in `__post_init__` and also covers a `replace()` call.
- `GuiConfig.from_env` does **not** read a session id from the environment. Callers generate one per launch (Task 2).

**Context:** the API's CORS config already allows any header (`allow_headers=["*"]`) and unknown headers are ignored by FastAPI, so sending this against a server that has not been updated is harmless.

- [x] **Step 1: Write failing tests:**
  - Header present with the right value when set; absent when `None`.
  - Header is sent on every method (`health` included, since it uses the same client).
  - Rejected ids: empty string, 65 characters, `"a b"`, `"x\r\nInjected: 1"`, non-ASCII. Accepted: 12-char hex, `a-b_C9`, exactly 64 characters.
  - `replace(config, session_id="bad id")` raises.
  - Existing `GuiConfig(...)` constructions and `from_env` behave as before.
- [x] **Step 2:** Run, confirm failures. **Step 3:** Implement. **Step 4:** `pytest tests/test_gui_*.py`, ruff, black, mypy on the two modules.
- [x] **Step 5:** Commit: `Send an optional session id header from the API client`

## Task 2: Packaging, entry point, and logging

**Files:**
- Modify: `pyproject.toml`
- Create: `grimoire/tui/__init__.py`, `grimoire/tui/__main__.py`, `grimoire/tui/logsetup.py`, `tests/tui/__init__.py`
- Test: `tests/tui/test_main.py`, `tests/tui/test_logsetup.py`

**Interfaces:**
- `pyproject.toml`: `[project.optional-dependencies] tui = ["textual>=0.80"]`; add `"textual>=0.80"` to `dev`; `[project.scripts] grimoire-tui = "grimoire.tui.__main__:main"`.
- `main(argv: Sequence[str] | None = None) -> int`. Takes `argv` so Click can call it and tests can pass args. `__main__` guard does `raise SystemExit(main())`.
- Options (stdlib `argparse`, **not** Click, to keep `grimoire-tui` startup free of the CLI group): `--url URL`, `--debug`, `--version`.
- `configure_tui_logging(session_id: str, *, debug: bool = False, log_dir: Path | None = None) -> Path | None`. Returns the absolute log file path so the app can tell the user where it is, or `None` when no directory was writable (logging is then off, never redirected to the terminal).

**Behaviour of `main`, in order:**

1. Parse args.
2. `try: import textual` except `ImportError`: print `Textual is not installed. Run: uv sync --extra tui` to stderr, return `1`. This check comes **before** any other grimoire import.
3. `session_id = uuid4().hex[:12]`; `configure_tui_logging(...)`.
4. `config = GuiConfig.from_env()`, then `dataclasses.replace(config, session_id=session_id)` and, when `--url` is given, `base_url=url.rstrip("/")`. The same `session_id` goes to the log file, so a server-side record can be matched to the TUI's log.
5. **Validate the URL ourselves**: it must be `http(s)://host[:port]` with no whitespace. `httpx.Client` accepts `"not a url"` and `"localhost:8001"` at construction and only fails on the first request, so relying on `ConnectionFailed` at startup (as the GUI does) would launch a UI where every action fails. Print a message that does **not** echo the value (it may come from an env var carrying credentials) and return `1`.
5b. Import `GrimoireApp` (an `ImportError` is logged with its traceback and reported as a one-line message pointing at the log file, return `1`), then `GrimoireClient(config)`; on `ConnectionFailed` print `exc.message`, return `1`.
6. `GrimoireApp(client, config, log_path).run()`; return `0` (or `app.return_code or 0`).
7. `finally: client.close()`.

**Logging details (each one a past footgun):**

- `logger.remove()` first. The default id-0 stderr handler is what would paint over the screen.
- File sink: `<log_dir>/grimoire-tui.log` (default `./logs`, matching the CLI's default, falling back to `~/.local/state/grimoire/logs` when that is unwritable, since an installed tool can be launched from a read-only directory), `enqueue=True`, rotation `"1 week"`, retention `"1 month"`. The format **must** contain `{extra[session_id]}`. `logger.configure(extra={"session_id": ...})` alone does nothing visible if the format omits it, and neither loguru's default format nor `DEFAULT_LOG_FORMAT` includes `extra`. Do not reuse either.
- Level `DEBUG` with `--debug`, else `INFO`.
- Route stdlib `logging` (httpx, anyio) into loguru with a small `InterceptHandler`, set on the root logger with `force=True`. Otherwise their warnings hit stderr via `logging.lastResort`.
- Do **not** import `grimoire.utils.logger`; its import-time `setup_logger()` re-adds the stderr sink.
- Observability (CLAUDE.md "Traceability"): the TUI is a client, so it logs the `session_id` locally and sends it to the API as `X-Session-Id` (Task 1b). The server-side half, binding it into log records and trace tags, is a follow-up PR below.

- [x] **Step 1: Write failing tests**
  - `main(["--version"])` prints a version and returns `0` (use `capsys`).
  - With `textual` hidden (`monkeypatch.setitem(sys.modules, "textual", None)`) `main([])` returns `1` and stderr contains `uv sync --extra tui`.
  - Malformed URLs (`"not a url"`, `"localhost:8001"`, `"ftp://host"`, `"http://"`, `""`, `"//host"`), from `--url` or from `GRIMOIRE_API_URL`, return `1` with no traceback and never construct the app.
  - There is no `--api-key` option (argparse rejects it).
  - Tests stub `textual` and `grimoire.tui.app` in `sys.modules`, so they run with or without Textual installed and before `app.py` exists. Only the `pyproject.toml` assertions need nothing at all.
  - `--url` overrides `GRIMOIRE_API_URL`; trailing slash stripped. Patch `GrimoireApp` with a recorder class.
  - The config handed to the client carries a valid `session_id`, and it is the same id that appears in the log lines.
  - `client.close()` is called even when `run()` raises.
  - Logging: after `configure_tui_logging(tmp_path)`, a `logger.info("x")` and a stdlib `logging.getLogger("httpx").warning("y")` land in the file, **nothing** reaches `capsys.readouterr().err`, and the line contains the session id.
  - `pyproject.toml` declares the `grimoire-tui` script and the `tui` extra (parse with `tomllib`).
- [x] **Step 2:** Run, confirm failures.

## Task 3: Pure formatting helpers

**Files:**
- Create: `grimoire/tui/formatting.py`
- Test: `tests/tui/test_formatting.py`

**Interfaces (all pure, all typed):**

```python
@dataclass(frozen=True)
class SourceView:
    title: str            # document_title or "(untitled)"
    text: str             # full chunk text, never truncated here
    score: float | None
    document_id: str      # "" if the server sent none
    chunk_ref: str        # "chunk 3" / chunk_id fallback, for display

def sources_from_query(resp: QueryResponse) -> list[SourceView]: ...
def sources_from_search(resp: SearchResponse) -> list[SourceView]: ...
def format_size(n: int) -> str            # 0 -> "0 B", 1536 -> "1.5 KB", cap at GB
def format_timestamp(iso: str | None) -> str   # "2026-10-01 14:03" or "-"
def truncate(s: str, width: int) -> str   # single ellipsis char, never negative width
def build_filter_dict(*, tags: str, source_type: str | None,
                      severity: str | None, cve_id: str) -> dict[str, Any] | None
def parse_top_k(raw: str) -> int | None   # 1..100 or None when invalid
SOURCE_TYPES: tuple[str, ...]; SEVERITIES: tuple[str, ...]
DOC_STATUSES: tuple[str, ...]; FILE_TYPES: tuple[str, ...]
```

`build_filter_dict` is a small re-implementation of `grimoire.cli.query._build_filter_dict`, **not an import** of it: that module pulls in `grimoire.cli.helpers`, which imports settings and violates the no-pipeline-imports constraint. It strips whitespace, splits `tags` on commas and drops empties, uses the server's key names (`tags`, `source_type`, `severity`, `cve_id`), and returns `None` when nothing is set so the client omits the key. A test asserts its output equals the CLI helper's for the same inputs, as a drift guard. That test imports the CLI helper and is skipped if the import fails.

- [x] **Step 1: Write failing tests:** boundaries (0, 1023, 1024, 10**12 bytes), `None`/garbage/timezone-bearing ISO timestamps, empty/whitespace/`"a, ,b"` tags, `parse_top_k("0"|"101"|"x"|""|" 7 ")`, citation with missing title and score, empty citation list.

**Notes from implementation:**

- The choice lists come from the real enums, not the CLI help text, which lists only five of the seven source types (it omits `ioc_list` and `unknown`). `SEVERITIES` likewise includes `unknown`.
- Drift guards assert `SOURCE_TYPES`, `SEVERITIES`, `DOC_STATUSES` and `FILE_TYPES` equal the real enums, and that `TOP_K_MIN`/`TOP_K_MAX` equal the `ge`/`le` constraints on `QueryRequest.top_k`. They skip if the pipeline modules cannot be imported, so the TUI's own tests never require them.
- `SourceView.score` is `None` for non-finite scores (`nan`/`inf`), so the widget never renders `nan`.
- `format_size` promotes a value that rounds to `1024.0` (`1048575 B` is `1.0 MB`, not `1024.0 KB`). `truncate` collapses whitespace so a cell is always one line. `parse_top_k` accepts ASCII digits only.
- Mutation-checked: dropping a severity, changing the top-k bound, treating chunk index 0 as missing, removing the rounding promotion, and removing whitespace collapsing each make a specific test fail.
- [x] **Step 2:** Run, confirm failures. **Step 3:** Implement. **Step 4:** Run, ruff, black, mypy.

**Notes from implementation:**

- Stale results are guarded by **two independent layers**: the worker checks `is_cancelled` before posting, and every request carries an id that the handler compares. **Notes from implementation:**

Writing this pane's tests exposed four problems in the app shell that the Search pane alone had hidden. Each was fixed and committed separately before this task, with its own regression test:

1. **Tab ping-pong** (`Fix tab switching ping-pong between panes that take focus`). Focusing a widget inside a pane makes `TabbedContent` activate that pane's tab. Hook callbacks queued for a tab the user had since left ran late, stole focus back, and flipped the tab; with two panes that each take the keyboard, they fought indefinitely (over 100 activations, 20 s of churn). The deferred callback now re-checks that its tab is still active.
2. **F2 undoing itself** (`Drop focus before switching tabs so the switch cannot undo itself`). Pressing F2 from the query box ended back on Search about 1 try in 6, because Textual refocuses a widget in the hidden pane and that late focus event reactivates the tab. `action_show_tab` now drops focus first. Measured: 21/25 before, 25/25 after.
3. **Hooks running twice** (`Run pane hooks once per tab switch`). Textual can report one switch twice, so `tab_shown()` ran twice, and a failed first load was silently retried. Hooks now run once per switch; a genuine second visit still runs them.
4. **Footer covering the last row** (`Stop the footer covering the last row of each pane`). `TabbedContent` was one row too tall, so the bottom row of every pane, including the range line here, sat under the key bar. It now has `height: 1fr`.

Pane-specific notes:

- Nothing is fetched until the tab is first shown (`tab_shown()`), so launching the TUI does not hit `/documents` for a tab nobody opened. If that first load fails, showing the tab again retries it.
- Stale responses use the same two independent guards as the Search pane (`is_cancelled` in the worker, a request id in the handler). Removing either one alone leaves the tests green; removing both fails three tests.
- `]` and `[` are hidden by `check_action` when they cannot apply, and the actions clamp themselves as well. A test calls the actions directly, because the hidden binding would otherwise mask the clamp.
- A page that is past the end (documents were deleted between two loads) falls back to the last page that exists, once, and cannot loop.
- A failed page change reverts the "target" page to the page still shown, so the next `]` retries it instead of skipping it.
- Hiding the focused table (an empty result) used to drop the keyboard onto nothing. Focus now moves to the Refresh button, and returns to the table when rows come back. It is only moved when the table *had* focus, so a reload landing while the user types in a filter does not take the keyboard.
- Type and status cells are capped at 24 characters and titles at 60, all as Rich `Text`, so a hostile or enormous value can neither inject markup nor widen the table.
- Tests wait on conditions (`_until`) rather than counting event-loop turns, and let startup finish first (`_launched`): a key pressed before the startup focus event lands is overridden by it. That race is a harness artefact, since a person cannot press a key that fast.
- The pane tests take about 90 s (70 tests, roughly 1.3 s each, dominated by app startup).
- Mutation-checked: wrong offset maths, a filter change that keeps the page, a full-path title fallback, markup-parsed cells, an error that wipes the table, a failed page not reverted, duplicate ids, no past-the-end fallback, markup on notifications, no focus hand-off, focus stolen from the user, and a refresh that loses the cursor each make a specific test fail.

## Task 8: CLI shortcuts and import hygiene

**Files:**
- Modify: `grimoire/cli/main.py` (the `--tui` flag, an early return for `tui`, registration)

**Interfaces:**

- `grimoire tui [--url URL] [--debug]`: a plain Click command that calls `grimoire.tui.__main__.main([...])` and exits with its return code. Registered in `main.py` with the others. The group callback returns early for it (see below), so it behaves exactly like `--tui`; `grimoire-tui` remains the canonical launcher.
- `grimoire --tui`: eager flag on the `cli` group.

```python
def _launch_tui(ctx: click.Context, _param: click.Parameter, value: bool) -> None:
    if not value or ctx.resilient_parsing:
        return
    from grimoire.tui.__main__ import main as tui_main   # lazy: keeps CLI startup fast
    ctx.exit(tui_main([]))

@click.option("--tui", is_flag=True, is_eager=True, expose_value=False,
              callback=_launch_tui, help="Launch the terminal UI and exit.")
```

Why eager: Click runs eager parameter callbacks **before** the group body, so this skips `setup_logger()` and `get_settings()` entirely. That is correct for the TUI (an HTTP client that needs neither) and avoids the stderr sink. `ctx.resilient_parsing` guard keeps shell completion and `--help` from launching the UI. `expose_value=False` keeps the flag out of `cli()`'s signature. Because the callback runs at parse time, `grimoire --tui --verbose` and `grimoire --verbose --tui` both launch, and `-v` has no effect (documented).

## Follow-up PRs (not part of the TUI PR)

Each is separate so the TUI PR stays reviewable and the server changes can be reviewed on their own.

- **A. Populate document counts and tags.** `GET /documents` fills `tag_count` and `chunk_count`, and `GET /documents/{id}` fills `tags`. Needs counting queries that avoid N+1 (grouped subqueries over the chunk and tag tables) and a test with documents that have and lack both. Once merged, the Documents pane gains two columns and the detail modal gains a tags row.
- **B. Server-side session id.** A pure-ASGI middleware (same style as `ContentLengthGuard` in `grimoire/api/main.py`, not `BaseHTTPMiddleware`) validates `X-Session-Id` against `^[A-Za-z0-9_-]{1,64}$`, ignores it when invalid, and binds it with `logger.contextualize(session_id=...)` for the request. The log format needs `{extra[session_id]}`. Tag MLflow/OTel runs with it where the server already creates them.
